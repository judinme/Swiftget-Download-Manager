1. Executive Overview & Mission Statement

1.1 Architectural Philosophy & Zero-Merge Invariant

SwiftGet is engineered as a modern, high-throughput, IDM-class download accelerator designed for Windows 10 and 11. It matches and exceeds the raw transfer performance, visual conventions, and browser takeover responsiveness of legacy Win32 utilities such as Internet Download Manager (IDM) and Free Download Manager (FDM), while delivering a 100% modern, secure, and clean architecture implemented in C# 12 and .NET 8 with WinUI 3.

The SwiftGet Core Architectural Invariant: "No-Merge Direct Sparse Allocation"
Legacy download managers typically download chunks into separate temporary files on disk (e.g. part001.tmp, part002.tmp). Upon reaching 100%, they execute an expensive, disk-thrashing concatenation merge. For a 50 GB file, this consumes 100 GB of temporary disk space and freezes the user's computer for several minutes. SwiftGet operates strictly on pre-allocated sparse files: all concurrent HTTP range streams and BitTorrent workers write directly to their assigned byte offsets via atomic RandomAccess.WriteAsync. When the last byte arrives, zero merge is required—the file is immediately finalized and closed.

2.2 Inter-Process Communication & Single-Instance Flow

SwiftGet guarantees that only one desktop UI process runs at any time. When a secondary download command is launched from the Windows command line, browser extension, or file association, the second process transfers the request payload to the running primary instance over the Windows Named Pipe: \\.\pipe\SwiftGet.SingleInstance.<Username>.

The message format is serialized as UTF-8 JSON containing the URL, initial filename, target directory, category, session cookies, referrers, custom headers, and browser window coordinate bounding boxes.

2.3 Data Storage Architecture (SQLite WAL Engine)

Download state persistence is managed by SqliteDatabase.cs in SwiftGet.Core. It is configured strictly with SQLite Write-Ahead Logging (WAL) to provide zero-lock contention between concurrent thread workers writing chunk telemetry and the UI reading items for display: 

PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

3. The SwiftGet Turbo Engine

3.1 SparseFileWriter: Zero-Overhead Direct Offset Allocation

The SparseFileWriter is a specialized unmanaged file wrapper implemented in SwiftGet.Engine.IO. It eliminates file fragmentation and guarantees instantaneous finalization:

  1. Sparse Flag Activation: Invokes Windows API DeviceIoControl with control code FSCTL_SET_SPARSE on NTFS/ReFS volumes. This allows the OS file system to allocate file ranges dynamically without requiring the disk to zero-fill gigabytes of space upfront.
  2. Direct Offset Streaming: Each connection worker maintains an asynchronous pipeline. Upon reading a chunk of network data (typically 64 KB to 256 KB), it executes: 
    await RandomAccess.WriteAsync(_fileHandle, buffer, fileOffset, cancellationToken);
  3. Instant Finalization: When all workers complete, the file length is truncated to the exact TotalBytes and the handle is flushed and closed. The file is immediately available on disk with zero merge delay.

3.2 Dynamic Midpoint Connection Splitting (1-32 Connections)

Traditional multi-threaded downloaders assign fixed chunk boundaries at the beginning of the transfer. If connection 1 encounters network congestion, the overall download stalls waiting for that single thread.

The SwiftGet DynamicRangeScheduler implements continuous dynamic midpoint splitting:

  • When a connection completes its assigned byte range, it does not terminate.
  • The scheduler scans all active connections and identifies the segment with the largest remaining byte distance: 
    remainingBytes = segment.EndOffset - segment.CurrentOffset + 1;
  • If remainingBytes >= minSplitSize (default: 1 MB), the remaining range is split at the midpoint: 
    splitPoint = segment.CurrentOffset + (remainingBytes / 2);
var oldEnd = segment.EndOffset;
segment.EndOffset = splitPoint - 1;

// Spawn new worker for second half
var newSegment = new DownloadSegment(splitPoint, oldEnd);
SpawnConnectionWorker(newSegment);
  • This guarantees that all available TCP connections remain 100% saturated until the entire file has finished transferring.

3.3 BBR-Style Link Capacity & Bottleneck Estimator

Implemented in CapacityEstimator.cs, SwiftGet continuously calculates:

  • Bottleneck Bandwidth (BtlBw): Windowed max-filter tracking delivered bytes over a 10-sample sliding window.
  • Minimum Round-Trip Time (RTprop): Windowed min-filter tracking TCP handshake latency and time-to-first-byte (TTFB).
  • Bottleneck Identification: Identifies whether the transfer is constrained by the local network adapter, ISP line throttling, or remote server per-connection bandwidth limits. When per-connection limits are detected, the concurrency controller scales up connections up to 32 to maximize throughput.

3.4 HTTP/2 Connection Trap Mitigation & ALPN Negotiation

Critical Performance Hazard: The HTTP/2 Multiplexing Bottleneck
Under standard .NET SocketsHttpHandler, if an HTTP/2 connection is negotiated, all subsequent range requests to the same host are multiplexed over a single TCP connection. This defeats multi-connection acceleration because all streams share one congestion window (cwnd). SwiftGet explicitly sets: 
handler.EnableMultipleHttp2Connections = true;
Furthermore, for multi-connection segmented downloads, SwiftGet configures HTTP version policy to RequestVersionOrLower with HTTP/1.1 prioritized, ensuring distinct parallel TCP sockets are established to bypass server-side per-connection traffic policing.

4. File Name Resolution & Compound Extension Recovery

4.1 Single Source of Truth: IFileNameResolver Protocol

A classic flaw in download managers is disjointed filename resolution: the initial dialog determines a filename from a URL slug, while the background engine writes to a different filename or loses the file extension.

SwiftGet unifies all filename logic into a single authoritative service: IFileNameResolver in SwiftGet.Core.IO.

4.2 Resolution Priority Matrix

When downloading a file, SwiftGet evaluates filename candidates strictly in order of descending authority:

Priority Level Source Condition Example Output
1 (Highest) User Lock User explicitly edited the filename in the dialog MyCustomName.zip
2 Content-Disposition RFC 6266 / RFC 5987 header returned by server Wondershare_UniConverter_18.zip
3 Final Redirect URL Filename present in redirected URI path ubuntu-26.04-desktop.iso
4 Query-String Hint URL parameter hints (e.g. ?filename=...) setup_installer.exe
5 Content-Type MIME Map Recover extension from MIME header download.tar.gz
6 Magic Byte Sniffer First 8 KB payload signature inspection archive.zip (PK header)
7 (Lowest) Fallback Slug URL path segment or generic placeholder download_a1b2c3d4.bin

4.3 Multi-Dot Compound Extension Engine

Standard .NET Path.GetExtension("archive.tar.gz") returns only .gz, which causes utilities to incorrectly categorize tarballs or corrupt complex archives upon renaming. SwiftGet includes an intelligent compound extension parser: 

// Correctly extracts compound archives
resolver.GetCompoundExtension("archive.tar.gz")  // Returns ".tar.gz"
resolver.GetCompoundExtension("data.tar.bz2")   // Returns ".tar.bz2"
resolver.GetCompoundExtension("backup.tar.xz")  // Returns ".tar.xz"
resolver.GetCompoundExtension("disc.iso")       // Returns ".iso"

5. Browser Integration & Native Messaging Bridge

5.1 Chromium MV3 & Firefox Interception Architecture

SwiftGet ships with custom extensions for Chromium (Google Chrome, Microsoft Edge, Brave, Opera, Vivaldi) and Mozilla Firefox built to Manifest V3 standards:

  • Chromium (MV3): Because Manifest V3 deprecates blocking webRequest in service workers, SwiftGet intercepts downloads using chrome.downloads.onCreated and onDeterminingFilename. The extension captures URL, session cookies, referrers, and user agents, instantly cancels and erases the browser's internal download item, and forwards the transfer payload to SwiftGet.
  • Firefox (MV3): Leverages Firefox's native support for blocking webRequest.onHeadersReceived, intercepting the request before the browser initiates disk allocation.
  • Wake-Up & Heartbeat: To prevent MV3 service workers from suspending during user clicks, the extension utilizes keep-alive alarms and reconnects on every download event.

5.2 Native Messaging Host Protocol (32-bit LE stdio)

The native messaging host (SwiftGet.NativeHost.exe) communicates with the browser via standard input and standard output. The framing protocol adheres strictly to browser specifications:

+-------------------------+-------------------------------------------------------------+ | Length Header (4 Bytes) | Message Payload (N Bytes UTF-8 JSON) | | 32-bit Little-Endian | {"action":"interceptDownload","url":"https://...","...":""} | +-------------------------+-------------------------------------------------------------+

5.3 Window Foreground Takeover: AllowSetForegroundWindow

Windows OS Restriction: Foreground Window Management
Windows restricts background processes from stealing focus via SetForegroundWindow. If a background process calls it directly, Windows merely flashes the taskbar icon.

SwiftGet solves this natively:
  1. When the user clicks a download in Chrome, Chrome is the current foreground process.
  2. Chrome spawns SwiftGet.NativeHost.exe, inheriting foreground privileges.
  3. The Native Host calls Win32 AllowSetForegroundWindow(swiftGetAppPid).
  4. WindowActivator.cs in SwiftGet.App uses AttachThreadInput and SetWindowPos(HWND_TOPMOST) to reliably pop the "Download File Info" dialog in front of the user immediately.

5.4 Keyboard Interception Modifiers

SwiftGet replicates the classic IDM keyboard modifier conventions:

  • Holding Alt (Bypass Switch): Completely disables SwiftGet interception for the clicked link, allowing the browser's built-in download manager to handle the file.
  • Holding Insert (Force Switch): Forces SwiftGet to capture the clicked link immediately, even if the file extension or MIME type is not on the automatic interception list.

6. BitTorrent Engine Subsystem

6.1 MonoTorrent Engine Integration

SwiftGet integrates a fully managed BitTorrent client engine built upon MonoTorrent in SwiftGet.Engine.Torrent:

  • DHT (Distributed Hash Table): Connects to bootstrap nodes (router.bittorrent.com, dht.transmissionbt.com) allowing trackerless torrent discovery.
  • Peer Exchange (PeX) & Local Peer Discovery (LSD): Automatically discovers swarm peers across local subnets and active swarms.
  • UPnP and NAT-PMP: Automatically maps external router ports dynamically for incoming peer connections.
  • Protocol Encryption: Enforces EncryptionTypes.All (PreferEncryption / RequireEncryption) to prevent ISP bandwidth throttling.

6.2 Magnet URI Protocol & BEP 9 Metadata Probing

When a magnet link (magnet:?xt=urn:btih:...) is captured:

  1. SwiftGet extracts the info-hash and display name using MagnetUriParser.
  2. The engine joins the DHT swarm and requests torrent metadata from active peers using BEP 9 (Extension for Transfer of Metadata).
  3. The "Add Torrent" dialog displays the complete file list, total sizes, and piece layout before the user confirms the download location.

6.3 Piece Map Visualization & Sequential Media Mode

SwiftGet features an interactive, real-time Piece Map control (PieceMapControl.xaml):

  • Downsamples swarms of 5,000+ pieces into visual 2D block arrays using PieceGridDownsampler.cs.
  • Colors blocks dynamically: Available (gray), Downloading (blue), Complete & Verified (green).
  • Sequential Mode: When enabled, pieces are prioritized from index 0 to N sequentially rather than rarest-first, allowing users to play video and audio files while the download is actively in progress.

7.3 DRM Detection & Strict Non-Circumvention Policy

Legal & Security Policy: DRM Protected Content
SwiftGet strictly adheres to digital copyright laws and anti-circumvention standards. If a stream contains Widevine, PlayReady, or FairPlay DRM encryption (detected via stream manifest headers pssh or _has_drm flags), SwiftGet immediately halts extraction and displays an informative notification that protected DRM streams cannot be captured.

9. Security Invariants & Threat Mitigation

9.1 Path Traversal Guard (CVE-Class Defenses)

Remote servers can attempt directory traversal attacks by supplying malicious filenames in Content-Disposition headers (e.g. filename="../../Windows/System32/evil.dll").

SwiftGet passes all paths through PathTraversalGuard.EnsureSafePath() in SwiftGet.Core.IO: 

// Strips directory separators, URL encodings, and verifies boundary
string safeFileName = Path.GetFileName(rawFileName);
string fullPath = Path.GetFullPath(Path.Combine(baseDirectory, safeFileName));
if (!fullPath.StartsWith(Path.GetFullPath(baseDirectory), StringComparison.OrdinalIgnoreCase))
{
    throw new SecurityException("Directory traversal attempt blocked.");
}

9.2 Mark-of-the-Web (Zone.Identifier) & Antivirus Hooks

Files downloaded from the public internet must be tagged to ensure the Windows security subsystem protects the user:

  • NTFS Alternate Data Streams (ADS): Upon completion, MarkOfTheWeb.cs attaches a Zone.Identifier stream indicating ZoneId=3 (Internet Zone).
  • Antivirus Scanning Hook: Automatically queries the Windows IAttachmentExecute API or launches the user's configured antivirus executable (Windows Defender, ESET, Bitdefender) against the completed file.
